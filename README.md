# TasteID

Личная библиотека вкусов: отзывы, «любимое», статистика и тир-листы.
Живёт на [tasteid.ru](https://tasteid.ru).

Сайт — статика без сборки: HTML, CSS и обычные `<script>`. Всё динамическое
делает Cloudflare Pages Functions, а хранилищем работает сам этот репозиторий.

## Как это устроено

```
index.html          публичная страница: вкладки Главная / Любимое / Отзывы /
                    Статистика / Тир-лист
js/                 фронтенд, подключается обычными <script> без модулей —
                    поэтому всё живёт в общей глобальной области
  utils.js          esc() и обработка не загрузившихся картинок.
                    ПОДКЛЮЧАТЬ ПЕРВЫМ на любой странице
  theme.js          читает site-settings.json, применяет тему, подписи,
                    порядок вкладок. Ставится в <head> до контента
  config.js         константы: оценки, типы, теги, категории
  api.js            загрузка reviews.json
  cards.js          общие куски карточек
  now.js / favorites.js / reviews.js / stats.js / tierlist.js
                    по файлу на вкладку
  passports.js      чужой паспорт: просмотр и сравнение (в настройках)
  import.js         перенос списка из чужих сервисов (экран мастера)
  import-formats.js разбор выгрузок: MAL/Шикимори XML, Goodreads, Letterboxd
  external-ids.js   разбор номеров тайтла в чужих базах из ссылок
  backup.js         выгрузка всего сайта в zip
functions/          Cloudflare Pages Functions
  _middleware.js    закрывает страницы админки от неавторизованных
  _shared.js        сессии, рейт-лимит, работа с GitHub Contents API
  api/*.js          по файлу на эндпоинт
*.json              данные (см. ниже)
chars/, covers/,    картинки. Отдаются с этого же домена, не с GitHub напрямую
title-covers/,
covers-backup/
scripts/check-json.js  проверка данных для CI
```

Админка — отдельные страницы: `/add` (отзыв), `/favorites-edit` (персонажи и
персоны), `/chars-edit` (тир-листы), `/reviews-order` (порядок любимого),
`/settings-edit` (настройки сайта), `/backup-history` (история версий файлов).

### Данные

| Файл                   | Что внутри                                               |
| ---------------------- | -------------------------------------------------------- |
| `reviews.json`         | отзывы и всё, что показывается на Главной                |
| `favorites.json`       | любимые персонажи и персоны                              |
| `characters-tier.json` | тир-листы                                                |
| `site-settings.json`   | тема, шкала оценок, подписи, порядок и видимость вкладок |

#### Номера тайтлов в чужих базах

У отзыва может быть поле `ids` — номера этого же тайтла на сторонних
сервисах, всегда парой «чья база + номер»:

```json
"ids": { "anilist": 145369, "mal": 1535 }
```

Нужны они для импорта списков (см. ниже): названия между сервисами не
сходятся никогда (перевод, регистр, двоеточие, год в скобках), а номера
сходятся всегда. Общая валюта по аниме и манге — номер MyAnimeList:
Шикимори использует его напрямую, AniList хранит рядом со своим.

Заполняется само: `/add` достаёт номер из ссылки на обложку, которую и
так вводят. Отдельного поля в форме нет. Правила разбора живут в
`js/external-ids.js` — один файл и для формы, и для скриптов, чтобы они
не разъехались.

Отдельной базы нет: админка через GitHub Contents API коммитит эти файлы прямо
в репозиторий. Побочный приятный эффект — каждое сохранение уже является
снимком, а история версий в `/backup-history` это просто список коммитов файла.

### Паспорта: просмотр и сравнение

Раздел «Паспорта» в `/settings-edit` умеет две вещи с чужим паспортом.
«Просмотр» показывает его как есть — полки его шкалы, его названия и
цвета, то есть примерно то, что человек увидел бы у него на сайте.
«Сравнение» кладёт два паспорта рядом, с упором на расхождения:
совпадения предсказуемы, спор интереснее.

Живёт это в настройках, а не в главных вкладках: заглядывают сюда
редко, а место в шапке дорогое.

Чужой паспорт приходит файлом — человек выгружает свой такой же кнопкой
там же. Сервер не нужен, всё считается в браузере, загруженный паспорт
лежит в `localStorage`. Когда появится обмен по коду, поменяется только
способ доставки файла.

Формат — `{ format: "tasteid-passport", version, gradeScale, items }`.
Шкала оценок едет вместе с паспортом, потому что у двух людей она может
быть разной: каждая оценка переводится в положение на своей шкале
(0 — лучшее, 1 — худшее), и дальше сравнимо что угодно с чем угодно.

Тайтлы сопоставляются сначала по номерам из `ids`, и только потом по
названию с типом. Ключ, под которым оказалось больше одной записи,
выбрасывается: три «Jujutsu Kaisen» (манга, второй сезон, третий) по
названию неразличимы, и лучше не сопоставить вовсе, чем показать
выдуманный спор с оценкой не от того сезона.

### Кнопка выбора файла

Их пять по сайту, и все они — `<label class="btn btn-ghost file-btn">`.
Раньше каждая несла свою копию внешнего вида кнопки (`.file-btn`,
`.pp-file-btn`, `.imp-file-btn`), и ни одна из этих копий не участвовала в
темах: тему знают `.btn` и `.btn-save`. Рядом с обычной кнопкой файловая
всюду выглядела чужой — прямоугольник против скруглённой пилюли.

Теперь вид берётся у `.btn`, а в `.file-btn` осталась только механика:
спрятать `input[type=file]` и разложить `<label>` как кнопку. Селектор
именно `.btn.file-btn` — на страницах-редакторах есть правила вроде
`.field label`, они специфичнее одного класса и перебивали бы и размер
шрифта, и `display`.

### Удаление встроенного, а не только своего

Встроенные теги, категории тегов, типы и роли лежат в `js/config.js` и
вырезать их оттуда нельзя — файл общий. Поэтому удаление встроенного
складывается в списки-исключения в `site-settings.json`, а применяется при
загрузке настроек: `hiddenTags`, `hiddenCategories`, `hiddenTypes`,
`hiddenSubtypes`. Свои теги и категории удаляются иначе — просто пропадают
из `customTags` / `customCategories`.

Категорию с тегами удалить нельзя: сначала теги переносятся в другую. Иначе
они остались бы висеть с несуществующей категорией.

Разделы вкладки «Статусы» удаляются все, кроме «Архива» — от него зависит
статистика. Перед удалением считается, сколько записей в этом статусе:
половина базы вполне может лежать в «Отложено», и узнать об этом надо до
удаления, а не после.

Коллекции тир-листа скрываются тем же `hiddenTierModes`, что и режим
«Тайтлы»: на вкладке это один ряд кнопок, и делить его на два списка
настроек значило бы врать про устройство. Удаляется и встроенная
«Персонажи» — файл `characters-tier.json` при этом остаётся лежать, а раз
завести коллекцию с тем же id из интерфейса нельзя (у новой он был бы с
суффиксом), рядом показывается строка возврата.

Пустой сохранённый `tierCollections` означает «все коллекции удалены», а не
«настроек ещё нет». Проверка идёт через `Array.isArray`, а не по длине
массива: иначе встроенная «Персонажи» возвращалась бы сама после каждого
удаления.

Три встроенных раздела «Любимого» (`removedFavSections`) удаляются вместе
со строкой в настройках, поэтому вернуть их иначе было бы нечем — рядом
показывается строка со стрелкой возврата. Сами записи в `favorites.json`
при этом никуда не деваются.

### Удаление отзыва

Ссылка «Удалить этот отзыв» внизу формы правки (`/add?edit=<id>`), у нового
отзыва её нет. Запрос уходит в `/api/delete-review` строго по числовому
номеру записи: под одним названием у человека спокойно лежат три «Jujutsu
Kaisen» (манга и два сезона), и удаление по названию однажды снесло бы не ту.

Подчищать за удалением нечего — ссылок на отзыв больше нигде нет. «Любимое»
держит признак в самой записи, а «Тайтлы» в тир-листе это вид поверх
`reviews.json`. Вернуть удалённое можно откатом `reviews.json` в «Истории
версий»; на экране это обещание и написано.

### Импорт списка

Раздел «Импорт» в `/settings-edit` переносит список из другого сервиса.
Формат узнаётся по файлу сам, выбирать ничего не нужно:

| Что                          | Откуда                | Файл | Есть номера?          |
| ---------------------------- | --------------------- | ---- | --------------------- |
| Аниме, манга, манхва, ранобэ | MyAnimeList, Шикимори | XML  | да, номер MAL         |
| То же, по нику               | AniList               | —    | да, оба номера        |
| Книги                        | Goodreads             | CSV  | да, свой номер и ISBN |
| Фильмы                       | Letterboxd            | CSV  | нет вовсе             |

AniList — единственный источник, который приходит не файлом: своей кнопки
«выгрузить» у него нет, зато открытый список отдаётся кому угодно по нику,
без ключа и без авторизации. Два запроса `MediaListCollection` (аниме и
манга), и список у нас. Обложки приезжают тем же ответом, поэтому за ними
второй раз не ходим — в отличие от файла, после которого приходится.

Две вещи, которые определили разбор:

Свои списки AniList отдаёт вперемешку со статусными, и запись лежит сразу
в двух — берём только статусные (`isCustomList: false`), иначе половина
списка приехала бы дважды.

Манхву и маньхуа AniList различает не типом, а страной происхождения
(`countryOfOrigin`), и делает это надёжнее MyAnimeList, где тип ставят
руками. Оценку просим в десятибалльном виде: у кого стоит стобалльная
шкала, тому AniList округлит сам, а экран соответствий остаётся тем же,
что у MyAnimeList, вместо сотни строк.

Проверить на живом API не удалось — из среды разработки anilist.co
недоступен; всё выше проверено на подставных ответах, повторяющих схему.

Из типов переносится всё, что различают MAL и Шикимори: TV, OVA, ONA,
спецвыпуски, полнометражки — в аниме; манга, манхва, маньхуа, ранобэ,
ваншоты и додзинси — в свои типы (`MAL_TYPE_MAP`). Избранное не
переносится ни с одного сервиса: в выгрузке формата MyAnimeList такого
поля нет вовсе.

Точный путь к выгрузке у каждого сервиса свой, и на экране он расписан до
пункта меню и имени файла (`IMPORT_SOURCES` в `js/import.js`). Совет
«выгрузи список» бесполезен тому, кто делает это впервые: экспорт спрятан
в настройках по-разному, а MyAnimeList и Letterboxd отдают архив вместо
файла — об этом надо сказать заранее, а не ошибкой разбора.

Разбор живёт в `js/import-formats.js`, по адаптеру на формат; наружу они
отдают одинаковую запись, и мастер работает с ней, не зная, откуда она.
CSV разбирается своей реализацией, а не `split(",")`: в выгрузках сплошь
и рядом запятые внутри кавычек, экранированные кавычки и переводы строк
посреди поля — наивный разбор разваливает файл молча.

Три шага, и записать в паспорт без явного подтверждения нельзя:

1. Файл разбирается в браузере — ничего никуда не уходит.
2. Человек видит, что нашлось, и сам решает, как чужие статусы и оценки
   ложатся на его собственные. Умолчания расставляются сами, но правятся.
3. По кнопке всё уходит одним запросом в `/api/import-reviews`.

Шкалы у сервисов разные: десятка у MAL, пятёрка у Goodreads, половинки
звёзд у Letterboxd. Раскладываются они по настоящим границам шкалы, а не
по встретившимся в файле значениям — иначе у человека, ставившего только
четвёрки и пятёрки, четвёрка уехала бы на худшую полку.

Если под чужой статус нет подходящего своего — чаще всего это «Брошено» —
его заводят прямо в списке, не уходя со страницы: разобранный файл живёт
в памяти и при уходе в другой раздел пропал бы.

Сопоставление с уже заведённым идёт сначала по номерам, потом по названию
с типом и годом. Неоднозначные ключи выбрасываются: три «Jujutsu Kaisen»
(манга, второй сезон, третий) по названию неразличимы. Для фильмов
название с годом — единственный вариант, но там он и работает лучше: у
фильма одно каноническое название и один год.

Обложек в выгрузках нет ни у кого. Аниме и манге их (плюс номер AniList и
год) дозапрашиваем у AniList по номеру MAL — ключей не требует. Книгам
хватает прямой ссылки на Open Library по ISBN, даже без запроса. Фильмам
нужен ключ TMDB: своей базы постеров без ключа не нашлось, а в выгрузке
Letterboxd нет даже номера фильма, только название с годом.

Ключ TMDB человек заводит сам (на экране расписано, где именно) и вводит
в разделе импорта. Он не обязателен: без него фильмы приезжают без
картинок, и ключ можно добавить потом, а обложки подтянуть повторным
импортом того же файла. Проверяется ключ сразу, запросом к
`/configuration`, — узнать об опечатке через двести запросов и список без
обложек было бы худшим из вариантов.

**Ключ хранится только в `localStorage` браузера.** Положить его в
`site-settings.json` было бы удобнее — синхронизировался бы сам, — но
репозиторий сайта открытый: ключ утёк бы в первый же коммит и остался бы
в истории навсегда. Цена решения: на другом устройстве ключ вводится
заново.

Запись идёт отдельным эндпоинтом, а не `save-review` в цикле: тот делает
коммит на каждый отзыв, и список в пятьсот записей означал бы пятьсот
коммитов. `import-reviews` читает файл один раз и сохраняет один раз.
Потолок — мегабайт на файл (ограничение Contents API), это примерно
шестьсот дописанных записей сверх имеющихся; дальше эндпоинт отвечает
понятной ошибкой, а не молча рвётся.

При перезаписи уже заведённых записей меняются только статус, оценка,
счётчик пересмотров и даты. Текст отзыва, «любимое», теги и название —
своё, нажитое, и импорт их не трогает ни при каких настройках.

### Авторизация

Пароль один, задаётся переменной окружения. При входе `/api/login` кладёт в KV
случайный токен сессии и ставит две куки:

- `tasteid_auth` — HttpOnly, по ней бэкенд пускает на запись;
- `tasteid_ui` — обычная, по ней фронтенд решает, показывать ли кнопки
  редактирования. На доступ она не влияет: любой запрос на запись всё равно
  проверяется по `tasteid_auth`.

## Настройка окружения

В Cloudflare Pages → проект → Settings → Functions нужно задать:

| Переменная       | Зачем                                    |
| ---------------- | ---------------------------------------- |
| `ADMIN_PASSWORD` | пароль для входа в админку               |
| `GITHUB_TOKEN`   | токен с правом записи в этот репозиторий |
| `GITHUB_REPO`    | `владелец/репозиторий`                   |

И один KV namespace binding:

| Variable name | Что это                                       |
| ------------- | --------------------------------------------- |
| `SESSIONS`    | хранилище сессий и счётчиков неудачных входов |

Без биндинга `SESSIONS` логин будет отвечать 500 — это сделано осознанно,
чтобы не было тихого режима «вход без сессий».

Локально те же значения кладутся в `.dev.vars` (файл в `.gitignore`).

## Разработка

```bash
npm install
npm run dev          # статика на http://localhost:8080
npm run check        # линтер + формат + проверка данных, то же самое гоняет CI
```

Отдельные команды:

```bash
npm run lint         # ESLint
npm run lint:fix     # ESLint с автоисправлением
npm run check:json   # данные парсятся, id отзывов уникальны,
                     # все локальные ссылки на картинки ведут на реальные файлы
npm run format       # Prettier
```

Разовые задачи по данным:

```bash
npm run ids:extract          # показать, какие номера достаются из ссылок
npm run ids:extract -- --write   # записать их в reviews.json
npm run ids:enrich           # показать, сколько номеров MAL запросится
npm run ids:enrich -- --write    # запросить у AniList и записать
```

Оба скрипта можно гонять повторно: уже проставленные номера не трогаются.
`ids:extract` работает без сети, `ids:enrich` ходит в AniList (ключей не
требует). Номера TMDB и IGDB из ссылок на обложки не достаются — там
лежит только путь к картинке, — так что их придётся спрашивать у API по
названию, а это уже с ключами.

`npm run dev` поднимает только статику — `/api/*` при этом не работает, и
страницы админки открываются без проверки пароля (её делает
`functions/_middleware.js`, а он живёт в Cloudflare). Чтобы поднять функции
локально, нужен `wrangler pages dev`.

### О стиле кода

Prettier настроен, но `js/`, `functions/` и `style.css` в `.prettierignore`:
там код выровнен по колонкам вручную, и прогон форматтера переписал бы больше
тысячи строк, стерев заодно историю `git blame`. Если решишь перейти на единый
машинный стиль — убери эти строки из `.prettierignore` и выполни
`npm run format` **отдельным коммитом**, чтобы он не смешался со смысловыми
правками.

## Что стоит знать, если правишь код

- **`js/utils.js` подключается первым.** В нём `esc()`, которым пользуются все
  остальные файлы.
- **Экранируй всё, что попадает в HTML.** `esc()` закрывает в том числе
  одинарную кавычку — это важно, потому что значения подставляются и внутрь
  одинарных кавычек тоже.
- **Не пиши URL из данных в inline-обработчики.** Для не загрузившихся картинок
  есть `imgFallbackAttrs(src, backup, placeholder)`: он кладёт ссылки в
  `data-`атрибуты, а реагирует на сбой один общий слушатель в `utils.js`.
  Данные должны оставаться данными.
- **Ссылки на свои картинки — относительные** (`/chars/…`), чтобы их раздавала
  наша CDN. `check:json` следит, что такая ссылка ведёт на существующий файл.
- **Кэш настраивается в `_headers`.** Там же заголовки безопасности; в CSP
  пока стоит `'unsafe-inline'` для скриптов — снять его получится, когда
  `onclick=` в разметке уступят место `addEventListener`.
- **Стили и скрипты подключаются с суффиксом `?v=N`.** Если правка делает
  разметку зависимой от нового CSS или JS — увеличь N сразу на всех
  страницах. Иначе браузер отдаст свежий HTML со старой копией стилей, и
  страница разъедется. Так уже случалось: правила вроде `.modal-overlay`
  переехали из страниц в `style.css`, а браузеры сутки отдавали
  закэшированный `style.css` без них — модалки раскрылись прямо в
  документе. `npm run check:assets` следит, чтобы версия не разъезжалась
  между страницами.
- **Не пиши код, который падает при устаревшем соседнем файле.** Точка
  входа вкладок в `index.html` обёрнута в `Promise.resolve(...)` именно
  поэтому: старый `theme.js` не отдаёт `window.themeReady`, и без обёртки
  страница навсегда зависала на «Загружаем…».
