# TasteID

Личная библиотека вкусов: отзывы, «любимое», статистика и тир-листы.
Живёт на [tasteid.ru](https://tasteid.ru).

Сайт — статика без сборки: HTML, CSS и обычные `<script>`. Всё динамическое
делает Cloudflare Pages Functions, а хранилищем работает сам этот репозиторий.

## Как это устроено

```
index.html          публичная страница: вкладки Главная / Любимое / Отзывы /
                    Статистика / Тир-лист
js/                 фронтенд, подключается обычными <script> без модулей —
                    поэтому всё живёт в общей глобальной области
  utils.js          esc() и обработка не загрузившихся картинок.
                    ПОДКЛЮЧАТЬ ПЕРВЫМ на любой странице
  theme.js          читает site-settings.json, применяет тему, подписи,
                    порядок вкладок. Ставится в <head> до контента
  config.js         константы: оценки, типы, теги, категории
  api.js            загрузка reviews.json
  cards.js          общие куски карточек
  now.js / favorites.js / reviews.js / stats.js / tierlist.js
                    по файлу на вкладку
  backup.js         выгрузка всего сайта в zip
functions/          Cloudflare Pages Functions
  _middleware.js    закрывает страницы админки от неавторизованных
  _shared.js        сессии, рейт-лимит, работа с GitHub Contents API
  api/*.js          по файлу на эндпоинт
*.json              данные (см. ниже)
chars/, covers/,    картинки. Отдаются с этого же домена, не с GitHub напрямую
title-covers/,
covers-backup/
scripts/check-json.js  проверка данных для CI
```

Админка — отдельные страницы: `/add` (отзыв), `/favorites-edit` (персонажи и
персоны), `/chars-edit` (тир-листы), `/reviews-order` (порядок любимого),
`/settings-edit` (настройки сайта), `/backup-history` (история версий файлов).

### Данные

| Файл                   | Что внутри                                               |
| ---------------------- | -------------------------------------------------------- |
| `reviews.json`         | отзывы и всё, что показывается на Главной                |
| `favorites.json`       | любимые персонажи и персоны                              |
| `characters-tier.json` | тир-листы                                                |
| `site-settings.json`   | тема, шкала оценок, подписи, порядок и видимость вкладок |

Отдельной базы нет: админка через GitHub Contents API коммитит эти файлы прямо
в репозиторий. Побочный приятный эффект — каждое сохранение уже является
снимком, а история версий в `/backup-history` это просто список коммитов файла.

### Авторизация

Пароль один, задаётся переменной окружения. При входе `/api/login` кладёт в KV
случайный токен сессии и ставит две куки:

- `tasteid_auth` — HttpOnly, по ней бэкенд пускает на запись;
- `tasteid_ui` — обычная, по ней фронтенд решает, показывать ли кнопки
  редактирования. На доступ она не влияет: любой запрос на запись всё равно
  проверяется по `tasteid_auth`.

## Настройка окружения

В Cloudflare Pages → проект → Settings → Functions нужно задать:

| Переменная       | Зачем                                    |
| ---------------- | ---------------------------------------- |
| `ADMIN_PASSWORD` | пароль для входа в админку               |
| `GITHUB_TOKEN`   | токен с правом записи в этот репозиторий |
| `GITHUB_REPO`    | `владелец/репозиторий`                   |

И один KV namespace binding:

| Variable name | Что это                                       |
| ------------- | --------------------------------------------- |
| `SESSIONS`    | хранилище сессий и счётчиков неудачных входов |

Без биндинга `SESSIONS` логин будет отвечать 500 — это сделано осознанно,
чтобы не было тихого режима «вход без сессий».

Локально те же значения кладутся в `.dev.vars` (файл в `.gitignore`).

## Разработка

```bash
npm install
npm run dev          # статика на http://localhost:8080
npm run check        # линтер + формат + проверка данных, то же самое гоняет CI
```

Отдельные команды:

```bash
npm run lint         # ESLint
npm run lint:fix     # ESLint с автоисправлением
npm run check:json   # данные парсятся, id отзывов уникальны,
                     # все локальные ссылки на картинки ведут на реальные файлы
npm run format       # Prettier
```

`npm run dev` поднимает только статику — `/api/*` при этом не работает, и
страницы админки открываются без проверки пароля (её делает
`functions/_middleware.js`, а он живёт в Cloudflare). Чтобы поднять функции
локально, нужен `wrangler pages dev`.

### О стиле кода

Prettier настроен, но `js/`, `functions/` и `style.css` в `.prettierignore`:
там код выровнен по колонкам вручную, и прогон форматтера переписал бы больше
тысячи строк, стерев заодно историю `git blame`. Если решишь перейти на единый
машинный стиль — убери эти строки из `.prettierignore` и выполни
`npm run format` **отдельным коммитом**, чтобы он не смешался со смысловыми
правками.

## Что стоит знать, если правишь код

- **`js/utils.js` подключается первым.** В нём `esc()`, которым пользуются все
  остальные файлы.
- **Экранируй всё, что попадает в HTML.** `esc()` закрывает в том числе
  одинарную кавычку — это важно, потому что значения подставляются и внутрь
  одинарных кавычек тоже.
- **Не пиши URL из данных в inline-обработчики.** Для не загрузившихся картинок
  есть `imgFallbackAttrs(src, backup, placeholder)`: он кладёт ссылки в
  `data-`атрибуты, а реагирует на сбой один общий слушатель в `utils.js`.
  Данные должны оставаться данными.
- **Ссылки на свои картинки — относительные** (`/chars/…`), чтобы их раздавала
  наша CDN. `check:json` следит, что такая ссылка ведёт на существующий файл.
- **Кэш настраивается в `_headers`.** Там же заголовки безопасности; в CSP
  пока стоит `'unsafe-inline'` для скриптов — снять его получится, когда
  `onclick=` в разметке уступят место `addEventListener`.
